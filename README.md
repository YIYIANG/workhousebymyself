# 微信小程序：小游戏合集 — 分步骤实施计划

目标：在微信小程序中实现一个“小游戏集合”，首批包含：
- 幸运转盘（转盘抽奖/转盘小游戏）
- 俄罗斯方块（Tetris）

说明：本计划以“普通小程序 + Canvas 2D”为技术路线（非“微信小游戏”独立平台），兼顾开发效率与审核流程。后续可按需迁移或复用到微信小游戏平台。


一、范围与里程碑

里程碑 M0 — 立项与准备（0.5 天）
- 确认小程序主体资质、类目与合规要求（是否涉及抽奖、广告、用户数据收集等）。
- 准备 AppID（测试号/正式号），开通云开发（可选）。
- 明确首批功能清单、验收标准与发布节奏。

里程碑 M1 — 项目初始化（1 天）
- 使用微信开发者工具创建“普通小程序”工程。
- 约定技术栈：原生小程序（WXML/WXSS/JS），按需引入 TypeScript（可选）。
- 初始化代码规范：ESLint + Prettier（可选），提交信息规范（commit lint，可选）。
- 设定目录结构与分包方案，提交初始骨架。

里程碑 M2 — 基础框架与通用能力（1.5 天）
- 全局导航：首页（游戏列表/入口）、关于页、设置页（音效开关等）。
- 通用组件：按钮、标题栏、弹窗、提示气泡、结果面板。
- Canvas 2D 封装：统一游戏循环、帧率控制、触摸/按键输入适配。
- 本地存储：通用存档与最高分记录（wx.getStorage/wx.setStorage）。
- 埋点与日志（可选）：基础错误捕获与性能日志。

里程碑 M3 — 幸运转盘 MVP（1 天）
- UI：可配置扇区（文本/图标/概率/颜色），开始按钮，转动动画。
- 逻辑：加速度/减速度转动，权重概率抽取，结果落点对齐。
- 配置：本地 JSON 配置项（奖项、权重、动画时长等）。
- 记录：最近 N 次结果历史，高亮扇区提示。
- 验收：中低端机 60fps 动画流畅，概率可回归校验。

里程碑 M4 — 俄罗斯方块 MVP（3–4 天）
- 画布：10x20 网格、单元格绘制、边框与阴影。
- 形状：7 种标准方块（I/J/L/O/S/T/Z），旋转系统（简化 SRS）。
- 逻辑：下落、左右移动、旋转、贴边/堆叠、消行与计分、关卡速度提升。
- 状态：暂停/恢复/重新开始，游戏结束判定。
- 操作：触摸区域映射（左移/右移/旋转/加速下落），或屏上虚拟按键。
- 记录：最高分与单局统计。
- 验收：在主流机型上稳定 50–60fps，无明显触控延迟。

里程碑 M5 — 排行与分享（可选，1–2 天）
- 本地排行榜：按游戏分别存储 Top N 成绩。
- 云端排行榜（可选）：开启云开发，匿名用户标识，上传/拉取成绩。
- 分享：海报分享/会话分享（遵循平台规范，不强制诱导）。

里程碑 M6 — 发布准备与上线（1 天）
- 全面自测：功能、性能、边界输入、低电量/锁屏恢复。
- 适配：深色模式、横竖屏（如需）、不同分辨率与刘海屏安全区域。
- 体验评分：启动时间、首屏渲染、包体与分包校验。
- 审核材料：应用描述、截图与类目合规自查。
- 提交审核与发布。


二、技术选型与目录结构

技术选型
- 原生微信小程序 + Canvas 2D。
- 可选增强：TypeScript、Less/Sass、ESLint/Prettier、CI（仅质量检查）。
- 云能力：微信云开发（Cloud Functions + Cloud DB）或自有 REST（如无后端则保持本地）。

建议目录结构（示例）
- project.config.json（小程序工程配置，提交）
- project.private.config.json（个人本地配置，忽略）
- miniprogram/
  - app.js / app.json / app.wxss
  - assets/（图片/音效）
  - components/（通用组件）
  - pages/
    - home/（首页：游戏列表与入口）
    - about/
    - settings/
  - games/（可按分包或普通目录组织）
    - wheel/（幸运转盘）
    - tetris/（俄罗斯方块）
- cloudfunctions/（可选：云函数）
- miniprogram_npm/（npm 构建产物，忽略）

分包建议
- 主包：home、about、settings、通用组件。
- 分包 A：games/wheel
- 分包 B：games/tetris
- 好处：减小首包体积、加快启动；访问游戏时再按需加载。


三、关键实现要点

通用游戏容器
- 统一 GameLoop：requestAnimationFrame 替代方案（setTimeout/Worker），可调帧率。
- 输入适配：touchstart/move/end 到“左/右/旋转/加速”等抽象事件。
- 渲染：Canvas 2D 封装 drawRect/drawText/drawImage 等常用方法。
- 状态管理：有限状态机（init/ready/running/paused/over）。

幸运转盘
- 几何与动画：角速度 α 递减到 0，最终角度落入目标扇区。
- 概率控制：支持权重表（权重=0 禁止中，调试模式固定结果）。
- 对齐：根据目标扇区中心角 + 指针偏移，计算初始角速度/减速时长。
- 可配置：扇区数量、颜色、文本、图标、概率、旋转圈数、时长、缓动曲线。

俄罗斯方块
- 数据结构：网格二维数组，方块形状矩阵，当前/下一块缓存。
- 碰撞判定：边界、落地、旋转踢墙（简化规则）。
- 下落与消行：定时 tick 下落；满行检测与清除、连击加分。
- 速度曲线：根据级别缩短 tick 间隔；加速下落键单独控制。
- 性能：批量绘制、最小重绘区域、尽量避免频繁 setData。

存储与排行榜
- 本地：wx.setStorageSync 保存最高分、设置项。
- 云端（可选）：匿名 openid 或设备指纹（合规前提下）+ 成绩上报接口。


四、质量与性能要求
- 启动时间（冷启动）：< 2.5s（视包体与设备而定）。
- 帧率：核心动画稳定 50–60fps；低端机最低 30fps 可接受。
- 兼容：Android/iOS 主流机型，微信基础库 ≥ 2.25.0。
- 无阻塞 UI：避免大数组 JSON 序列化/频繁 setData；Canvas 绘制放在游戏循环内。
- 错误处理：try/catch + 控制台日志；关键路径埋点（可选）。


五、合规与风控
- 抽奖/转盘：仅“娱乐用途”文案，避免“现金/虚拟货币/诱导分享”的敏感设计；如涉及奖品需遵循平台规则并补充活动细则与客服入口。
- 隐私：不采集不必要的个人信息；如接入排行榜需明确告知与用途；遵循平台隐私合规要求。
- 广告（可选）：Banner/激励视频需在适合的节奏展示，不诱导点击。


六、验收标准（MVP）
- 首页可进入“幸运转盘”“俄罗斯方块”，均可正常开始/结束一局。
- 转盘可配置扇区与概率，动画流畅，结果可回归测试。
- 俄罗斯方块具备移动/旋转/加速/消行/计分，稳定运行 3 分钟无异常。
- 设置页可开关音效；各游戏本地最高分可记录与展示。
- 通过自测清单与基本兼容性验证，可提交审核。

八、后续规划
- 新游戏：贪吃蛇、2048、打地鼠、飞行射击等；每个游戏独立分包。
- 音效与皮肤：主题皮肤、节日活动皮肤，音效资源按需加载。
- 社交玩法：本地对战/异步挑战（合规前提下）。
- 数据化：A/B 配置、游戏时长与留存分析。


开发提示
- 先完成“骨架与通用能力”，再做转盘（简单验证渲染/动画），最后攻坚俄罗斯方块（复杂度高）。
- 强调性能：减少 setData 次数，Canvas 绘制与逻辑解耦，必要时用 OffscreenCanvas（基础库支持情况下）。
- 保持配置化：游戏参数、难度、扇区权重皆可配置，便于后续活动迭代。
